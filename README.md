# 8-bit-computer-architecture

8-Bit Computer Architecture Using Verilog HDL

1. Project Overview

This project focuses on the design and implementation of an 8-bit computer architecture using Verilog Hardware Description Language (HDL). The design is developed using Xilinx Vivado and implemented on an FPGA development board.

The system consists of a Control Unit, Arithmetic Logic Unit (ALU), registers, RAM, Program Counter, and an 8-bit data bus. These components work together to fetch, decode, and execute instructions.

The project provides practical experience in digital electronics, computer architecture, RTL design, simulation, and FPGA hardware implementation.

2. Project Objectives

- To design an 8-bit computer architecture using Verilog HDL.
- To understand the operation of computer architecture components.
- To implement individual modules and integrate them into a complete system.
- To understand data transfer between registers, memory, and the ALU.
- To implement instruction execution using a Control Unit.
- To verify the design through simulation.
- To implement and test the architecture on an FPGA development board.

3. System Architecture

The computer architecture consists of several interconnected modules that perform instruction processing, data storage, arithmetic operations, and control functions.

3.1 Control Unit

The Control Unit manages the overall operation of the computer. It decodes instructions and generates control signals to coordinate data transfers and operations between different components.

3.2 Program Counter (PC)

The Program Counter stores the address of the instruction to be fetched next. It normally updates as instructions are processed and can be loaded with a target address when a jump instruction is executed.

3.3 Instruction Register (IR)

The Instruction Register stores the current instruction fetched from memory. The Control Unit uses the instruction information to determine the operation to be performed.

3.4 A Register

The A Register temporarily stores data used during processing. It can provide an operand for arithmetic or logical operations, depending on the implemented design.

3.5 B Register

The B Register stores another data operand for processing. The stored value can be transferred to the ALU or other components through the data bus.

3.6 Arithmetic Logic Unit (ALU)

The ALU performs arithmetic and logical operations on data. Depending on the implemented design, these operations may include:

- Addition
- Subtraction
- AND operation
- OR operation
- XOR operation

The ALU produces the result of the selected operation.

3.7 Memory Address Register (MAR)

The Memory Address Register stores the address of the memory location being accessed. It helps coordinate memory access operations.

3.8 Random Access Memory (RAM)

RAM stores instructions and/or data according to the memory organization of the project. The computer accesses memory during instruction fetching and data operations.

3.9 Output Register

The Output Register stores the result intended for the output section. The result can be observed through the output interface provided by the design.

3.10 Flag Register

The Flag Register stores status information generated by operations, where implemented. Examples include carry and zero flags, which can indicate arithmetic status or whether a result is zero.

3.11 8-Bit Data Bus

The 8-bit data bus transfers data between the computer's internal components. It provides a common path for data communication between registers, memory, and processing units.

4. Instruction Execution Cycle

The computer processes instructions through three main stages.

4.1 Fetch Cycle

During the fetch stage, the computer retrieves an instruction from memory using the appropriate address. The instruction is transferred to the Instruction Register for further processing.

4.2 Decode Cycle

During the decode stage, the Control Unit identifies the instruction and determines the required operation. It generates the control signals needed for instruction execution.

4.3 Execute Cycle

During the execute stage, the computer performs the operation specified by the instruction. This may involve arithmetic or logical processing, data transfer, memory access, or changing the program flow.

5. Instruction Set

The architecture may support instructions such as the following, depending on the implemented instruction set.

5.1 LDA – Load Accumulator

The LDA instruction loads data from the specified source or memory location into the accumulator or designated register.

5.2 ADD – Addition

The ADD instruction performs an addition operation using the specified operands. The result is stored in the designated destination.

5.3 STA – Store Accumulator

The STA instruction stores the accumulator or designated register value in the specified memory location.

5.4 XOR – Exclusive OR

The XOR instruction performs a bitwise Exclusive OR operation between two operands. Each output bit is 1 when the corresponding input bits are different.

5.5 OUT – Output

The OUT instruction transfers the designated data value to the output register or output interface.

5.6 NOP – No Operation

The NOP instruction does not perform a normal data-processing operation. The computer continues according to the instruction sequencing implemented in the design.

5.7 HLT – Halt

The HLT instruction stops normal instruction execution according to the implemented control logic.

5.8 JMP – Jump

The JMP instruction changes the normal instruction sequence by transferring control to a specified program address.

When the Control Unit identifies a JMP instruction, the Program Counter is updated with the target address. The next instruction is then fetched from that address instead of following the normal sequential order.

Example:

If a JMP instruction specifies address 10, the Program Counter is loaded with address 10. The next instruction is fetched from that location.

The exact behavior of each instruction depends on its implementation in the Verilog source code.

6. Development Tools and Technologies

The following tools and technologies are used in the project:

- Verilog HDL: Used to describe the digital hardware modules.
- Xilinx Vivado: Used for RTL design, simulation, synthesis, implementation, and bitstream generation.
- FPGA Development Board: Used to implement and test the design in hardware.
- XDC Constraints File: Used to assign FPGA package pins and define relevant hardware constraints.

7. Design and Module Integration

The computer architecture is designed using separate Verilog modules. Each module performs a specific function, making the system easier to understand, test, and maintain.

The modules are integrated through appropriate data connections and control signals. The 8-bit data bus provides data communication, while the Control Unit coordinates the operations of the system.

The integrated design is then used for simulation and hardware implementation.

8. Simulation and Verification

Simulation is an important stage in verifying the functionality of the computer architecture before hardware testing.

A Verilog testbench applies inputs and monitors outputs to check whether the modules operate as expected.

The verification process may include:

- Checking arithmetic and logical operations.
- Verifying register transfers.
- Checking instruction execution.
- Observing the Program Counter behavior.
- Testing memory access.
- Checking output data.
- Verifying jump instruction behavior.

Simulation results are used to identify and correct design errors before proceeding to hardware implementation.

9. Hardware Implementation on FPGA

The designed 8-bit computer architecture is implemented on an FPGA development board using Xilinx Vivado.

FPGA implementation allows the Verilog design to operate as digital hardware rather than being limited to simulation.

9.1 Hardware Implementation Procedure

1. Design the individual computer architecture modules using Verilog HDL.
2. Integrate the modules into the complete system.
3. Run behavioral simulation using the testbench.
4. Configure the FPGA package pin assignments using the XDC constraints file.
5. Run synthesis to convert the RTL design into a hardware representation.
6. Run implementation to map the design to the FPGA resources.
7. Generate the programming bitstream.
8. Program the FPGA development board with the generated bitstream.
9. Test the implemented design using the available input and output interfaces.

9.2 FPGA Hardware Testing

The implemented design can be tested by applying the required inputs and observing the available outputs.

Hardware testing helps verify the behavior of the architecture on the FPGA board. The observed results depend on the programmed design, clock configuration, pin assignments, and available input/output interfaces.
